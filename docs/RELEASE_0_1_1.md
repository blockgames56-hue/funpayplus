# FunPay Plus 0.1.1 — исправления и проверка

Версия исправляет обработку команд плагинов, завершение фоновых задач и восстановление интерфейса после ошибок загрузки.

## Исправления

- Команды включённых плагинов работают при выключенном автоответчике. Обычные автоответы при этом не отправляются; сообщения не обрабатываются задним числом при последующем включении автоответчика.
- Выключенные SMM и другие модули не принимают команды пополнения/проверки и ввод цели для ожидающего заказа.
- При завершении приложения останавливаются задачи плагинов, почты, закупщика и аренды, затем соединения аккаунтов и база. Очистка выполняется также при ошибке запуска или исключении в lifespan.
- Ошибка одного соединения не прерывает закрытие остальных. Уже завершившийся с ошибкой воркер не блокирует остановку аккаунта и его удаление.
- Проверка аккаунтов не создаёт новый воркер одновременно с остановкой старого. Начало завершения блокирует повторный запуск даже во время чтения базы. Повторный старт менеджера не создаёт дубли планировщика.
- Ошибка загрузки раздела больше не убирает весь интерфейс: сохраняется меню, появляется сообщение и кнопка перезагрузки. Возврат в обзор и повторная загрузка проверены с намеренно сорванным запросом JavaScript-модуля.
- Desktop отслеживает аварийное завершение своего backend. При занятом порте или сбое запуска показывается сообщение; завершившийся процесс не блокирует отключение и выход. PID проверяется перед очисткой, чтобы событие старого процесса не затронуло новый.

## Проверка

На 22.11.2026 полный независимый прогон: **32 тестовых модуля, 411 Python-тестов, 0 ошибок**. Каждый модуль запускался с отдельным временным хранилищем. Также прошли Ruff, Python/JSON, TypeScript, Vite, проверка адресов сервера и сборка Windows MSI/NSIS.

Интерфейс проверен в браузере с подставными сетевыми ответами и принудительным сбоем загрузки раздела. Аварийное завершение backend проверено в настоящем Windows Tauri/WebView2 на отдельном профиле и папке данных: локальная база не создавалась, завершение собственного процесса было корректно распознано. Рабочий магазин при этих проверках не изменялся.

Протоколы в локальной папке `.verification`: `full-audit-final.json`, `remaining-runtime-tests.log`, `remaining-core-tests.log`, `remaining-plugin-switches.log`, `remaining-desktop-build.log`, `remaining-final-desktop.log`. Эти файлы и временные данные не входят в архив GitHub.

Предыдущая проверка подключения к серверу и FunPayAPI описана в [аудите VPS/FunPayAPI](VPS_FUNPAY_AUDIT.md). Настоящий внешний VPS, публичный HTTPS и операции с реальными платежами этим прогоном не проверены.

## Обновление

Полностью завершите приложение через «Выход» в трее и остановите отдельно запущенный локальный сервер, затем установите `FunPay Plus_0.1.1_x64-setup.exe`. Каталог данных и идентификатор приложения сохранены; новая миграция базы не требуется.

Для GitHub используйте заново собранный `artifacts/FunPay-Plus-GitHub.zip`: в нём исходники 0.1.1 без локальных баз, ключей и сборочных каталогов. Инструкция сервера: [SERVER.md](SERVER.md).

# Проверка серверного режима — 0.1.6

## Исправления

- Удалён верхний переключатель «Работа бота» рядом с аватаркой. Аватарка, имя и
  управление аккаунтами в их разделе сохранены; включённость аккаунтов не меняется.
- События WebSocket объединяются в фиксированные окна 250 мс. Поток событий не
  откладывает обновления бесконечно, а медленные запросы не отменяются и не
  дублируются каждым новым сообщением. Уведомления обрабатываются сразу.
- После закрытия компонента ожидающий запрос WebSocket-ticket больше не создаёт
  лишнее соединение. Таймер обновления очищается; поздние события игнорируются.
- Gunicorn получает 110 секунд на корректную остановку, Docker — 120 секунд.
  Это согласует завершение фоновых операций и последующее закрытие процесса.

## Что проверено

- 200 событий интерфейса объединяются в одно обновление нужных данных; следующие
  окна работают отдельно, ping не вызывает запросы, чужие плагины не обновляются.
- Браузер: одно действующее WebSocket-соединение после StrictMode, удалённый верхний
  переключатель, сохранённые имя/аватарка, две серии по 200 событий во время
  задержанных запросов не создают повторных запросов той же страницы.
- 20 параллельных запросов /api/health успешно завершаются, пока синхронный SDK FunPay
  продолжает ждать в отдельном потоке. Соединения БД возвращаются в пул.
- Медленный подписчик сохраняет не более 256 событий, удерживая последние данные.
- Отключение браузера убирает подписку и не останавливает серверную автоматизацию.
- Повторный запуск/остановка workers, восстановление очереди и защита от повторных
  сообщений; соединение VPS без ключа; установщик и перенос данных.

Проверки выполнены на Windows, с временной SQLite и имитацией FunPay. Нагрузочный
сценарий выполняется с отладочным asyncio и не является замером скорости Linux VPS
или PostgreSQL. Docker Engine и реальный VPS в этой среде недоступны: сборку Linux-
контейнеров, реальную нагрузку, перезагрузку VPS и внешний HTTPS здесь не проверяли.
Реальные покупки и сообщения покупателям не выполнялись.

## Серверные настройки

Один ASGI-worker сохраняет единственность фоновых обработчиков. Compose включает
restart: unless-stopped, постоянные тома БД/файлов, проверку готовности БД и API,
ротацию контейнерных логов (3 файла по 10 МБ). Docker включается установщиком после
перезагрузки. Если сервисы остановлены вручную, запустите deploy/server.sh start.
Healthcheck показывает состояние; сам по себе он не перезапускает unhealthy-
контейнер. Политика перезапуска применяется при завершении процесса.

Основания настроек: [Docker restart policy](https://docs.docker.com/engine/containers/start-containers-automatically/),
[Gunicorn graceful timeout](https://gunicorn.org/reference/settings/#graceful-timeout).

## Установка

На Ubuntu/Debian VPS, под root:

```bash
curl -fsSL https://raw.githubusercontent.com/blockgames56-hue/funpayplus/main/install.sh | bash -s -- --repo https://github.com/blockgames56-hue/funpayplus.git
```

Без домена на компьютере:

```powershell
ssh -L 8080:127.0.0.1:8080 root@SERVER_IP
```

Откройте http://localhost:8080. Ключ входа не требуется. Туннель нужен для панели;
фоновые задачи работают после его закрытия и выключения компьютера.

Обновление существующей установки, на VPS под root:

```bash
cd /opt/funpay-plus && bash deploy/server.sh update
```

При переносе с Windows каталог обычно ~/funpay-plus. [Полная инструкция](SERVER.md).

# Шаблоны сообщений и перенос Auto Steam Rent

Исходники проверены в `C:\Users\User\Desktop\FunPay Plus\плагины`. Вариант пути `FunPayPlus` без пробела отсутствует. Исходные плагины не запускались: тексты извлечены через AST, бизнес-операции перенесены в FastAPI и React. Контрольные суммы шести файлов и ссылки на исходные строки сохранены в `SOURCE_MESSAGE_AUDIT.json`.

## Шаблоны

Вкладка **«Шаблоны сообщений»** содержит 77 событий. Есть поиск, категории, выбор получателя, подсказки тегов, локальный предпросмотр, отдельное сохранение и сброс каждого текста. Для редактора используются большие поля `#111116` с зелёной рамкой фокуса. Старая общая форма с двумя текстами скрыта у модулей выдачи.

Все 19 ключей из задания присутствуют. Дополнительно доступны команды аренды, предупреждение за 30 минут, бонус за отзыв, продление, фото и ошибки проверок, сообщения SMM, Steam Points, Stars и обращения в поддержку.

16 стандартных текстов адаптированы непосредственно из исходников: семь текстов проверки клуба, пять Steam Points, подтверждение Stars, два обращения AutoTicket, приём оплаты SMM. Остальные шаблоны оформлены для событий существующих адаптеров. Сообщение оригинала «Средства возвращены» заменено текстом о проверке продавцом: приложение не утверждает, что возврат состоялся, без подтверждённой операции возврата.

`MessageFormatter` заменяет только простые `{name}`. Выражения, обращения к атрибутам, индексы и спецификаторы Python запрещены. Значения не интерпретируются повторно: ключ, содержащий фигурные скобки, остаётся ключом. Неизвестные теги отклоняются API. Ранее изменённые пользователем тексты сохраняются и показываются редактором; явный сброс имеет приоритет над старой настройкой.

Переопределения хранятся в SQLite, таблица `message_templates`. Шаблон применяется перед отправкой. Пароли аренды и результат выдачи сохраняются зашифрованными; журнал содержит номера операций и статусы, без паролей, кодов Guard и секретов maFile.

| Событие | Где применяется |
| --- | --- |
| Оплата, запрос и подтверждение получателя | `integrated_jobs` |
| Завершение, сбой выдачи, команды SMM | `integrated_jobs` |
| Выдача/продление/окончание аренды, Guard, предупреждения | `steam_rentals` |
| Фото, повторные попытки, одобрение, таймаут, отмена | `rental_verification` |
| Ручная выдача и продление | `rental_api` |
| Заявка Steam, ожидание дружбы, подтверждённый подарок/буст | `fulfillment` |
| Ошибка региона, приглашения или отсутствие бустов | явное действие оператора в очереди выдачи |
| Результат поставщика и сбой до получения товара | `app_route` |
| Обращения в поддержку | `support_tickets` |

Roblox остаётся модулем проверки геймпасса: готовые тексты ошибок и выдачи не создают отсутствующую операцию покупки. Успешная выдача Steam Gift и Discord подтверждается оператором после фактической операции, как и до этого изменения. Такие режимы указаны в обзоре модулей.

## Перенос аренды

Telegram-меню исходника заменено разделами приложения. Это перенос возможностей, а не запуск Cardinal внутри веб-приложения.

| Функции Auto_Steam_Rent | Раздел приложения и поведение |
| --- | --- |
| Dashboard, monitor:status/jobs/errors | Счётчики пула, аренды, очередь заказов, статусы Steam и журнал |
| Добавление, просмотр и изменение аккаунта | «Аккаунты Steam»: мастер карточка → доступ → лоты |
| Добавление без maFile | Черновик; секреты зашифрованы, автовыдача недоступна |
| Добавление до создания лотов | Привязки можно назначить позже; проверенный аккаунт доступен для ручной выдачи |
| maFile, SteamID, авторизация | JSON разбирается и проверяется; вход в Steam подтверждается перед готовностью |
| Один аккаунт для нескольких лотов | Таблица `rental_account_bindings`; один общий статус занятости |
| Заморозка, удаление | Заморозка свободного пула; удаление только без истории аренды |
| Просмотр логина/пароля владельцем | «Инструменты Steam», отдельное окно с автоматическим очищением |
| Guard | Официальное время Steam, код владельцу или действующему покупателю |
| Смена пароля | Фоновая задача, сохранение кандидата до обращения к Steam, независимая проверка нового входа |
| Сбой смены пароля / перезапуск | Карантин, сохранение кандидата, проверка через восстановление; неизвестный пароль не считается действующим |
| Ручная выдача | Выбор аккаунта и существующего чата FunPay, срок в минутах; без фиктивного оплаченного заказа |
| Ручное продление | Добавление минут, уведомление и ключ операции, исключающий повторное добавление времени |
| Завершение и отмена | Закрытие доступа через подтверждённую смену пароля; возврат денег — отдельное решение |
| Автовыдача по лоту | Проверенная оплата, покупатель, количество и точная привязка ID лота |
| Лот продления | Привязка к основному правилу; продлевает однозначно определённую действующую аренду, в том числе ручную |
| Скрытие пустых лотов | Только при включённой настройке; восстанавливаются только ранее скрытые этим плагином лоты |
| Поддержание лота продления активным | Отдельный переключатель |
| Предупреждения за 30 и 10 минут | Отдельные отметки отправки; сбрасываются после продления |
| Отзыв 5★ | Один бонус на заказ, ближайшая активная аренда покупателя; учитываются и заказы продления |
| Заметки и чёрный список | «Покупатели»; новые выдачи блокируются, включая постановку в ЧС после оплаты |
| Журнал, поиск, выгрузка, очистка | «Логи», фильтры, CSV, отдельное подтверждение очистки; история аренд не удаляется |

Команды покупателя: `!аренда`, `!аккаунты`, `!время`, `!код(логин)`, `!код логин`, `!продлить(логин)`, `!продлить логин`, `!помощь`, `!cancel` / `/cancel` во время проверки фото. Команды Guard и срока проверяют реального отправителя и действующую аренду. Продление возвращает ссылку на подходящий лот, а не общую просьбу написать продавцу. Неоднозначные привязки требуют выбора владельца.

## Проверка ПК-клубов

В предоставленном исходнике `_pc_load_config` принудительно включает ручной режим и выключает поиск изображений. В приложении ручной процесс работает по умолчанию; дополнительные проверки включаются владельцем явно.

- До фото резервируется свободный аккаунт. Резерв сохраняется между попытками и освобождается при окончательном отказе, таймауте, отмене или возврате заказа.
- Ожидание, фотография, срок, число отказов, отчёт и решение сохранены в зашифрованном payload заказа. Перезапуск анализа переводит заказ на ручное решение, без автоматического одобрения.
- Таймер ограничивает отправку фотографии. Полученное фото, ожидающее администратора, не отклоняется только из-за времени ответа продавца.
- После отказа запрашивается новое фото; после заданного числа отказов заказ требует ручного решения. Одобрение запускает выдачу только один раз.
- Отсутствие EXIF или GPS означает «неизвестно», а не «верификация пройдена».
- Проверка времени использует настраиваемый часовой пояс и допуск. Метаданные можно подделать, поэтому они не выдаются за доказательство подлинности.
- Геопроверка: собственный список клубов и радиус; отдельно включаемый поиск OpenStreetMap/Overpass. Координаты отправляются внешнему сервису только при включении поиска.
- Поиск совпадений: Google Cloud Vision WEB_DETECTION, проверка полных совпадений за пределами FunPay. Недоступный API переводит результат продавцу. Парсинг CAPTCHA-страниц Yandex из старого исходника не используется как надёжная проверка.
- ИИ: Gemini и API, совместимые с Chat Completions — OpenAI, Groq, OpenRouter, собственный HTTPS endpoint. Нужны действующий ключ и модель с изображениями. Фото и до 10 референсов передаются только при включённой проверке.
- Автовыдача возможна только при положительном результате всех включённых проверок. Ошибка сети, неправильный JSON или неоднозначный результат оставляет решение продавцу.
- Референсы загружаются через интерфейс и хранятся зашифрованными. Лимиты: 10 изображений, 8 МБ и 24 Мп на файл. Анализ Pillow выполняется вне основного event loop, параллельно не более двух фотографий.
- Уведомления используют общие настройки Telegram или заданный список Chat ID. Отсутствие Telegram не отменяет очередь проверки в приложении.

Не перенесены сторонняя лицензирующая инфраструктура, установка пакетов во время работы, глобальная подмена библиотек, чужие реквизиты и небезопасное присваивание нового пароля при неудачной операции Steam. Зависимости устанавливаются штатной сборкой, авторизация Steam и смена пароля подтверждаются реальным ответом сервиса.

## Проверка

- Полный backend suite: 183 теста; сценарии сети и финансовых операций используют моки.
- Миграция `0011` проверена на копии пользовательской SQLite: сохранены количества строк, `integrity_check=ok`, `foreign_key_check` пуст, поддерживаются аккаунты без лотов и аренды без искусственного заказа.
- Playwright: изменение/сброс/предпросмотр шаблона, неверные теги, мастер Steam, несколько лотов, ручная выдача, решение по фото и сохранение настроек; ширины 1440 и 390 px.
- `tsc -b`, Vite production build и Ruff.

Рабочие операции покупки, выдачи, смены пароля и отправки покупателям во время разработки не запускались. Для настоящей аренды владелец подключает собственный Steam-аккаунт, maFile и лоты, затем включает плагин.

Документация внешних проверок: [Gemini — изображения](https://ai.google.dev/gemini-api/docs/image-understanding), [Google Cloud Vision — Web Detection](https://docs.cloud.google.com/vision/docs/detecting-web), [Overpass](https://dev.overpass-api.de/command_line.html).

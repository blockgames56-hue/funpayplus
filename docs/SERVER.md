# FunPay Plus на сервере 24/7

После установки обработка сообщений, заказов, автоподнятие и включённые плагины выполняются на VPS. Браузер и компьютер можно закрыть. В интерфейсе остаются те же настройки; включение конкретных автоматизаций сохраняется в базе и не меняется установщиком.

## Что загрузить на GitHub

Репозиторием должна быть папка, в которой лежат `install.sh`, `docker-compose.yml`, `backend/` и `apps/`. Готовый архив исходников создаётся командой `python deploy/package-source.py`: `artifacts/FunPay-Plus-GitHub.zip`. Распакуйте его и загрузите содержимое в корень репозитория, например `blockgames56-hue/funpayplus`, ветка `main`.

В архив не попадают локальная база, `.env`, ключи Windows, аккаунты, `node_modules`, сборки и резервные копии. Данные магазина переносятся отдельной командой по SSH. GitHub не нужен для хранения паролей.

## Новая установка одной командой

Нужен VPS с Ubuntu/Debian, SSH-доступом и правами root/sudo. Пример выполняется **в SSH-консоли сервера**. Замените `blockgames56-hue/funpayplus` на свой репозиторий:

Если вошли как root и sudo не установлен, уберите слово `sudo` из команд этой инструкции. Скрипт переноса с Windows выбирает этот режим автоматически.

```bash
curl -fsSL https://raw.githubusercontent.com/blockgames56-hue/funpayplus/main/install.sh | sudo bash -s -- --repo https://github.com/blockgames56-hue/funpayplus.git
```

Установщик скачивает код в `/opt/funpay-plus`, устанавливает Docker Engine и Compose при их отсутствии, включает Docker после перезагрузки, создаёт случайные ключи, собирает интерфейс/backend, применяет миграции и запускает контейнеры. Если `curl` отсутствует, сначала установите его: `sudo apt-get update && sudo apt-get install -y curl`.

Для публичной панели с HTTPS направьте DNS домена на сервер и разрешите входящие TCP 80/443. Затем используйте:

```bash
curl -fsSL https://raw.githubusercontent.com/blockgames56-hue/funpayplus/main/install.sh | sudo bash -s -- --repo https://github.com/blockgames56-hue/funpayplus.git --domain panel.example.com
```

Панель: `https://panel.example.com`. Выберите режим запуска; ручной ключ не требуется.

Первый выпуск сертификата зависит от DNS и доступности портов. Установщик проверяет HTTPS и авторизованный API после запуска контейнеров; при ошибке контейнеры сохраняются для диагностики, а установка не объявляется успешной. Установка без домена доступна через SSH-туннель: **на ПК** выполните `ssh -L 8080:127.0.0.1:8080 root@SERVER_IP` и откройте `http://localhost:8080`. Отключение туннеля закрывает только доступ к панели; сервер продолжает работу.

Уже скачанный проект запускается одной командой `sudo bash install.sh` или `sudo bash install.sh --domain panel.example.com`. Повторный запуск сохраняет существующие ключи. Если скачивание/сборка были прерваны, выполните эту команду из существующего каталога. Изменить каталог или ветку при установке можно параметрами `--dir /opt/my-panel` и `--ref BRANCH_OR_TAG`.

Для приватного репозитория сначала клонируйте его обычным авторизованным способом через SSH/GitHub CLI, затем запустите локальный `install.sh`. Не помещайте GitHub-токен в команду установки.

## Перенос текущих данных с Windows одной командой

Для переноса нужен Python с зависимостями проекта (`.venv-core` или `.venv`), штатные OpenSSH и tar. Команда выполняется **из PowerShell в корне проекта на том же Windows-пользователе**, у которого работало приложение. Перед переносом завершите FunPay Plus через «Выход» в трее и остановите локальный сервер на порту 8765.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\deploy\push-vps.ps1 -Server SERVER_IP -User root -Repository https://github.com/blockgames56-hue/funpayplus.git -Domain panel.example.com
```

Параметры `-Repository` и `-Domain` необязательны. Без Repository передаются текущие исходники, но обновление через `git pull` недоступно. С Repository сначала загрузите эти исходники на GitHub: локальный код и выбранная ветка должны совпадать. Для SSH на другом порту используйте `-Port 2222`. На сервере нужен свободный каталог `~/funpay-plus`; существующая установка не перезаписывается.

Переносятся аккаунты FunPay, настройки и привязки плагинов, заказы, история чатов, шаблоны, товары и пулы выдачи, Steam-данные/maFile, почтовые настройки и аватарки. SQLite импортируется в PostgreSQL одной транзакцией; перед импортом копия обновляется до текущей схемы. Ключ Windows DPAPI раскрывается только на исходном ПК для передачи через SSH. Почтовые пароли перешифровываются под серверный ключ в копии базы. Оригинальные данные ПК не изменяются.

По умолчанию берутся данные `storage/` в корне проекта. Для установленного desktop-приложения укажите его папку данных:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\deploy\push-vps.ps1 -Server SERVER_IP -User root -StoragePath "$env:APPDATA\com.funpayplus.terminal" -Repository https://github.com/blockgames56-hue/funpayplus.git -Domain panel.example.com
```

После завершения откройте панель или укажите её адрес в desktop-приложении. Ключ входа не нужен. Без домена скрипт покажет команду SSH-туннеля.

Не запускайте исходную локальную автоматизацию после переноса: одновременно работать должен один экземпляр магазина. Для управления магазином с ПК используйте браузер или «Подключиться к своему серверу» в desktop-приложении, указав адрес панели. Вход в панель открыт без пароля. Для личного доступа используйте SSH-туннель или собственное ограничение доступа на reverse proxy. Пока требуется доступ к панели через туннель, SSH-соединение держат открытым; для самой автоматизации оно не нужно.

При выборе VPS desktop-клиент не запускает локальный backend. При переключении из локального режима он сначала останавливает свои локальные задачи; если остановка не подтверждена, переключение не выполняется. WebSocket и повторное подключение проверены в настоящем Windows-клиенте: [протокол аудита](VPS_FUNPAY_AUDIT.md).

Если серверная сборка прервалась, данные для повторной попытки сохраняются в `.transfer`. Продолжение **на сервере**: `cd ~/funpay-plus && sudo bash deploy/finish-upload.sh --resume` (при необходимости добавьте `--domain panel.example.com`). Импорт в непустую базу отклоняется. Исходный PostgreSQL переносите резервной копией PostgreSQL, а не скриптом экспорта SQLite.

## Управление сервером

Выполняйте из каталога установки, например `/opt/funpay-plus` или `~/funpay-plus`:

```bash
sudo bash deploy/server.sh status   # состояние контейнеров
sudo bash deploy/server.sh logs     # последние записи и поток логов
sudo bash deploy/server.sh backup   # база, файлы и ключи в backups/
sudo bash deploy/server.sh update   # копия данных, git pull --ff-only, сборка и перезапуск
sudo bash deploy/server.sh restart
sudo bash deploy/server.sh stop
sudo bash deploy/server.sh start
```

Обновление делает резервную копию и сохраняет Docker-тома; файл `.env` не меняется. Резервное копирование ненадолго останавливает backend для согласованной копии данных, затем запускает его, если он работал. При ошибке сборки обновление останавливается без заявления об успехе. Миграции запускаются одним backend-процессом; не увеличивайте число gunicorn workers или реплик.

Данные находятся в томах `pg_data` и `backend_storage`, HTTPS-сертификаты — в `caddy_data`/`caddy_config`. Названия томов имеют префикс Compose-проекта. Для новых установок он зафиксирован как `funpay-plus`. Не выполняйте `docker compose down -v`: эта команда удаляет тома. Сохраняйте всю папку созданной резервной копии: `database.dump`, `storage.tar.gz` **и `.env`**. Без исходного SECRET_KEY сохранённые секреты не откроются. Копии на том же сервере не заменяют копию на отдельном носителе.

Восстановление на чистом сервере: установите код, остановите backend, замените `.env` на сохранённый (с тем же Compose-префиксом), запустите PostgreSQL, восстановите `database.dump` через `pg_restore --clean --if-exists --no-owner -U pulse_user -d pulse`, распакуйте `storage.tar.gz` в том `/app/storage` и выполните `server.sh start`. Имя и пароль PostgreSQL берутся из сохранённого `.env`. Не восстанавливайте копию поверх работающего магазина.

## Проверка этой реализации

Автотесты проверяют сохранность аккаунтов и настроек при импорте, отказ повторного импорта, перенос DPAPI-ключа Windows, перешифровку почтовых паролей, сохранение исходных данных, исключение секретов из GitHub-архива, параметры HTTPS и повторный запуск установщика с сохранением ключей. Bash и PowerShell проверяются на синтаксис. Проверка Bash-установщика использует подставной Docker и не заменяет запуск контейнеров.

В текущей Windows-среде Docker Engine и Linux VPS недоступны. Реальная сборка Linux-образов, PostgreSQL, выпуск HTTPS-сертификата и перезагрузка VPS здесь не проверены. Их проверяют при первом развёртывании по фактическому адресу сервера. Установка Docker основана на официальных инструкциях [Ubuntu](https://docs.docker.com/engine/install/ubuntu/) и [Debian](https://docs.docker.com/engine/install/debian/).

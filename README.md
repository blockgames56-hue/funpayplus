## Быстрый запуск в Windows

Нужны Python 3.12+, Node.js 20.19+ или 22+, интернет для установки зависимостей. Для запуска в браузере Rust не требуется.

1. Откройте `start.cmd` в этой папке. Он создаст `.venv-core`, установит зависимости, соберёт интерфейс, применит миграции и запустит сервер.
2. Откройте **http://127.0.0.1:8765**.
3. Выберите локальную установку. Ключ для входа не требуется.
4. В разделе «Аккаунты» подключите свою сессию FunPay через `golden_key`.
5. Синхронизируйте чаты и лоты. Создание правил, включение автоответчика и автоподнятия выполняется отдельно в интерфейсе.

Для входа в приложение ручной ключ не нужен. `golden_key` FunPay по-прежнему нужен для подключения сессии магазина.

Запуск из PowerShell:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\deploy\start.ps1
```

Режим разработки:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\deploy\start.ps1 -Dev
# Во втором терминале, из этой папки:
npm run dev
# http://127.0.0.1:5173
```

При сетевой ошибке установки скрипт завершается с ошибкой. Он не сообщает об успешном запуске после неудачной установки или сборки. Повторный запуск продолжает установку в существующее окружение.

## Linux и macOS: запуск в браузере

### Протокол FunPay

Исходное ТЗ содержит расхождения с доступным эталонным клиентом. В реализации использован протокол из предоставленного кода:

- Runner получает форму `application/x-www-form-urlencoded`; `objects` и `request` сериализуются в JSON внутри полей.
- Подписки: `chat_bookmarks`, `orders_counters`, `chat_node`. Для диалогов сохраняются теги и ID последнего сообщения.
- Загрузка изображения: `/chat/upload`, затем сообщение `[img:ID]`.
- Профиль читает `body[data-app-data]`, `userId`, `csrf-token`, а также резервные HTML-селекторы.
- Перед автовыдачей отдельно запрашивается `/api/orders/get` и проверяются продавец, покупатель и оплаченный статус.
- Изменяющие запросы не повторяются автоматически при неизвестном результате. Безопасные запросы используют таймаут и ограниченные повторы с задержкой.
- При CAPTCHA/403 воркер сообщает об ошибке и ожидает вмешательства. Автоматическое решение CAPTCHA не реализовано.

`FUNPAY_TRANSPORT=curl` включает альтернативный транспорт `curl_cffi`; по умолчанию используется `httpx`.

### Надёжность выдачи

Пул содержит запас товаров: один товар резервируется для одного заказа, и тот же товар не достаётся следующему покупателю. Резерв и состояние `sending` записываются до сетевой отправки.

При таймауте или неподтверждённом ответе состояние становится `uncertain`; при аварийном завершении может остаться `sending`. Автоматического повтора нет. В разделе «Финансы» кнопка «Проверить выдачу» показывает зарезервированное сообщение. После проверки чата можно завершить выдачу вручную и подтвердить локальный статус.

Начальная история заказов отмечается как историческая: она не запускает массовую выдачу или благодарности. Исторические заказы без надёжной даты не учитываются как сегодняшние продажи. Для новых записей дата означает время первого обнаружения. История сообщений сохраняется в локальную БД по мере получения Runner; загрузка предыдущих сообщений в интерфейсе читает эту сохранённую историю.

Финансовый показатель после комиссии — расчёт по заданному проценту, без себестоимости, налогов и фактических комиссий отдельных сделок. Его нельзя считать бухгалтерской чистой прибылью.

## Сервер 24/7: установка одной командой

Загрузите в GitHub содержимое `artifacts/FunPay-Plus-GitHub.zip` (создание архива: `python deploy/package-source.py`). В корне репозитория должны быть `install.sh`, `docker-compose.yml`, `backend/` и `apps/`.

На Ubuntu/Debian VPS замените `blockgames56-hue/funpayplus` на свой репозиторий и выполните:

```bash
curl -fsSL https://raw.githubusercontent.com/blockgames56-hue/funpayplus/main/install.sh | sudo bash -s -- --repo https://github.com/blockgames56-hue/funpayplus.git --domain panel.example.com
```

Домен предварительно направьте на VPS; без домена уберите `--domain panel.example.com` и используйте SSH-туннель. Установщик скачивает код, устанавливает Docker/Compose, генерирует ключи, применяет миграции и запускает приложение. Docker включается после перезагрузки; контейнеры используют `restart: unless-stopped`, постоянные тома и ограничение размера логов. Компьютер и SSH-соединение для работы магазина не нужны.

**Перенос текущих данных с Windows:** завершите локальное приложение/сервер, затем из корня проекта:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\deploy\push-vps.ps1 -Server SERVER_IP -User root -Repository https://github.com/blockgames56-hue/funpayplus.git -Domain panel.example.com
```

Аккаунты, настройки, чаты, заказы, плагины и зашифрованные секреты передаются по SSH; SQLite импортируется в PostgreSQL. Для desktop-данных добавьте `-StoragePath "$env:APPDATA\com.funpayplus.terminal"`. Личные базы и ключи в GitHub загружать не нужно. Не запускайте параллельно локальную автоматизацию после переноса.

**Управление** из каталога установки:

```bash
sudo bash deploy/server.sh status
sudo bash deploy/server.sh backup
sudo bash deploy/server.sh update  # копия данных, обновление из GitHub, сборка
```

Полная инструкция: [установка, перенос, подключение с ПК и резервные копии](docs/SERVER.md). Реальное развёртывание на VPS и выпуск сертификата в текущей Windows-среде не проверены.

## Лоты и бонусы

Редактор лотов загружает поля категории из формы FunPay. Можно создать до 20 одинаковых лотов и рассчитать ориентировочную цену по себестоимости, указанной комиссии и наценке. Поля загрузки изображений пока не поддерживаются; изображения редактируются на FunPay. При сетевой ошибке сохранения не выполняется автоматический повтор: проверьте лот на площадке перед следующей попыткой.

Бонусы начисляются за новые завершённые заказы в RUB один раз на заказ. Возврат снимает ранее начисленные баллы. Покупатель проверяет баланс командой `/баллы` и получает настроенную награду командой `/бонус`. Баллы учитываются приложением, не являются валютой FunPay. Акция на лот реально меняет его цену для всех покупателей и пытается восстановить исходную по окончании срока; если цена изменена вручную или результат сетевого запроса неизвестен, требуется проверка в разделе «Бонусы и акции». Персональную скидку отдельному покупателю площадка через этот механизм не предоставляет.

### Десктоп-приложение и удалённый сервер

Десктоп-приложение (Tauri) по умолчанию работает с локальным sidecar-сервером `127.0.0.1:8765`. Чтобы подключить его к своему серверу, на экране входа откройте «Подключиться к своему серверу», введите только адрес панели (`https://terminal.example.com`). Сессия создаётся автоматически. Режим сохраняется; «Вернуться к локальному режиму» переключает обратно. Origin'ы десктоп-клиента (`tauri://localhost`, `http://tauri.localhost`) разрешены на сервере по умолчанию.

## Desktop / Tauri

Исходники иконок и конфигурация установщиков включены. Windows-установщики собраны в `artifacts/desktop`; в архив GitHub включены исходники. Сборка macOS не проверена. Нужны Rust/Cargo и системные зависимости Tauri: MSVC/WebView2 для Windows или Xcode tools для macOS.

Из корня проекта, после установки Python/Node-зависимостей:

```powershell
.venv\Scripts\python.exe -m pip install -r backend\requirements-dev.txt
.venv\Scripts\python.exe deploy\build-sidecar.py
npm run dev -w @funpay-plus/desktop
# Windows installer:
npm run build -w @funpay-plus/desktop -- --bundles nsis
```

На macOS используйте `.venv/bin/python` и `--bundles dmg`. Sidecar собирается на целевой ОС и получает суффикс Rust target triple автоматически. Перед desktop-запуском остановите браузерный backend на порту 8765.

Tauri создаёт отдельный токен доступа для своего процесса и передаёт его интерфейсу через IPC. База и ключ шифрования хранятся в каталоге данных приложения. Закрытие окна сворачивает его в трей; пункт «Выход» останавливает sidecar.

## Хранение и резервные копии

- `golden_key`, пароли прокси, Telegram-токен, пул ключей и зарезервированные тексты выдачи шифруются AES-GCM.
- Локальная база: `storage/pulse.db`, SQLite WAL, внешние ключи и каскадное удаление.
- Аватарки берутся из блока `.avatar-photo` профиля FunPay, проходят проверку адреса и формата изображения, сохраняются в `storage/avatars` на семь дней и в IndexedDB браузера. Если загрузка не удалась, показываются инициалы. Авторизованный API отдаёт изображения и в desktop-приложении.
- WebSocket передаёт события чатов, заказов и бонусов в интерфейс. Сообщения покупателей из чёрного списка сохраняются в истории, но не вызывают автоответы и Telegram-уведомления. Журнал событий записывается через асинхронную сессию БД.
- Ключ шифрования: `SECRET_KEY` из окружения/`.env` либо `storage/encryption.key`.
- Для восстановления нужна **и база, и исходный ключ шифрования**. Для Docker сохраняйте `.env` вместе с резервной копией PostgreSQL и тома `backend_storage`.
- Вход без ручного ключа; браузерная сессия использует HttpOnly cookie, desktop — автоматически полученную сессию. Публичный адрес панели открывается без пароля; для личного доступа используйте SSH-туннель.
- Удаление аккаунта удаляет его локальные чаты, сообщения, лоты, заказы и правила. Операции на самом FunPay при этом не выполняются.

## Оставшиеся отличия от полного ТЗ

- Подписанное автообновление Tauri не подключено: нет инфраструктуры релизов, публичного ключа и update feed.
- `auto_restore` присутствует в модели, но фоновое восстановление проданных лотов не реализовано.
- Подтверждение заказа и спор выполняются через ссылку на интерфейс FunPay; отдельных автоматических запросов этих действий нет.
- Дата регистрации покупателя, число отзывов и геолокация прокси не загружаются.
- CopyLots переносит публичные тексты и позволяет заполнить собственные поля категории; изображения и закрытые данные продавца не копируются.
- Синхронизация заказов читает доступную страницу списка, не полный исторический архив. Одновременно опрашиваются последние 100 известных диалогов; расширение охвата требует настройки пакетирования.
- Нет измерения потребления RAM и проверки обещания «30–60 МБ», подписанных установщиков и проверки на Windows/macOS/VPS.

Эти ограничения перечислены явно. Интерфейс не содержит демонстрационной выручки; сетевые ошибки и неопределённые результаты отправки отображаются пользователю.
# Автоответчик и AutoTicket

В «Автоответах» можно включить задержанные ответы, команды и регулярные выражения,
а также шаблоны AutoTicket для сообщений с меткой «Арбитраж». Обработчики получают
события новых сообщений после записи истории в SQLite. Автоматическая отправка
ограничена одним запросом на аккаунт каждые три секунды; повторные сообщения
арбитража учитываются в таблице `ticket_events`. Уведомления AutoTicket включаются
отдельным событием «Споры и арбитраж» в настройках Telegram.

AutoTicket использует регулярный HTTP опрос чатов FunPay. Отдельный API для списка
споров и действие «Печатает…» в используемом протоколе не подтверждены, поэтому
обнаруживаются только сообщения с меткой арбитража и фиктивный статус не отправляется.
Первый цикл опроса импортирует историю без автоматических действий. При неизвестном
результате отправки тикета повторная отправка заблокирована до ручной проверки.


Подробности шаблонов сообщений и расширенной аренды Steam: [карта переноса и проверки](docs/MESSAGE_TEMPLATES_AND_STEAM_RENT.md).
